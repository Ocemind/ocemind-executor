# 借鉴清单落地计划（2026-11）

> 来源：2026-11-01 对手头两个细分工具（CR TubeGet、小豆芽/新榜）的逆向结论。
> 原则：**只抄「低成本、直接改变体验或防事故」的部分**，不抄重资产业务。
> 每一条都要能指着界面说「这里变好了」，否则不做。

## 单条交付定义

每条都要过这四关，缺一不算完：

1. **改完**：代码 + 一句能在界面上看到的效果；
2. **测过**：`python -m pytest -q` 全绿，新行为有测试；
3. **看过**：起本地服务，用 Playwright 点一遍并截图，确认交互没坏；
4. **记过**：`CHANGELOG.md` 对应版本记一笔，计划表状态打勾。

## 版本策略

- 攒够一批再发版（比如 1+2+3 一起发 2.5.0），不要一条一发；
- 发版沿用现有流程：改版本号 → `git tag vX.Y.Z` → push，CI 签名打包；
- 本机已能自更新（2.4.0 起 updater 走设置里的代理），发出去就是点一下的事。
